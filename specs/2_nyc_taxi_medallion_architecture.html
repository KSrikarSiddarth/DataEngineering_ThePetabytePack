NYC Taxi Medallion Architecture

Transition from the raw TLC schemas (Yellow, Green, FHV, HVFHV, Taxi Zone Lookup) to the Silver and Gold schemas required by the KPIs.

Layer overview

Bronze: raw, as landed

Exact copy of the TLC files. Original column names. No type casting.
bronze.yellow_tripdata
  • tpep_pickup_datetime, tpep_dropoff_datetime
  • trip_distance, fare_amount, tip_amount, total_amount, Airport_fee
bronze.green_tripdata
  • lpep_pickup_datetime, lpep_dropoff_datetime
  • trip_type, ehail_fee
bronze.fhv_tripdata
  • pickup_datetime, dropOff_datetime
  • dispatching_base_num, SR_Flag
bronze.fhvhv_tripdata
  • request_datetime, on_scene_datetime, pickup_datetime, dropoff_datetime
  • base_passenger_fare, driver_pay, tips, shared_match_flag
bronze.taxi_zone_lookup
  • LocationID, Borough, Zone, service_zone
→

Silver: cleaned, conformed

One schema for all trip types. Typed, deduplicated, validated.
silver.trips (one row per trip)
  • trip_id, service_type (yellow | green | fhv | fhvhv)
  • request_ts, on_scene_ts, pickup_ts, dropoff_ts
  • pu_location_id, do_location_id
  • distance_miles, duration_sec, passenger_count
  • payment_type, base_fare, tip_amount, total_amount
  • driver_pay, shared_request_flag, shared_match_flag
  • dq_dropoff_before_pickup, dq_zero_distance, dq_unmatched_zone
silver.dim_zone
  • location_id, borough, zone, service_zone
silver.dim_payment_type / silver.dim_ratecode
  • Code-to-label lookups from the shared code tables
silver.dim_hvfhs_company
  • hvfhs_license_num to name (Juno, Uber, Via, Lyft)
silver.batch_run_log
  • One row per file load: source_file, tlc_published_date, bronze_rows, silver_rows, duplicates_removed, schema_hash, start_ts, end_ts, status
silver.ml_features
  • Trip-level and zone-hour-level feature sets for Spark ML: lags, hour, day of week, holiday flag, zone profile
  • Excludes post-trip fields (dropoff time, total amount, tip) where they would leak the label
→

Gold: KPI-ready marts

One table per KPI group. Built for dashboards and analysis.
gold.trips_daily
  • Trip count and share, by date and service_type
gold.demand_hourly
  • Trips by hour of day and day of week
gold.zone_od_daily
  • Trips by pickup and dropoff zone pair, by date
gold.revenue_daily
  • Total revenue, average fare, average fare per mile, tip rate (Yellow and Green)
gold.trip_efficiency_daily
  • Average duration, average speed, average distance
gold.hvfhv_economics_daily
  • Driver pay as share of base fare, fee share of passenger cost
gold.hvfhv_service_daily
  • Wait time, response time, shared-ride match rate
gold.data_quality_daily
  • Null rates, dq flag counts, unmatched zones, row counts per file
Batch history marts (monthly)
  • gold.trips_monthly: growth, rolling average, seasonality, mix shift
  • gold.revenue_monthly: fare per mile, card vs cash, fee impact
  • gold.trip_efficiency_monthly: duration and speed trend
  • gold.demand_monthly_hourly: peak-hour profile change
  • gold.zone_od_monthly: zone growth and decline
  • gold.hvfhv_economics_monthly: driver pay share trend
Batch pipeline health
  • gold.batch_run_metrics: success rate, freshness, reconciliation, schema drift, runtime, backfill
  • gold.data_quality_monthly: duplicate rate, late corrections, null and unmatched-zone drift
Spark ML outputs
  • gold.ml_demand_forecast, gold.ml_fare_predictions, gold.ml_duration_predictions
  • gold.ml_tip_predictions, gold.ml_wait_predictions, gold.ml_shared_match_predictions
  • gold.ml_zone_clusters, gold.ml_demand_pattern_clusters, gold.ml_trip_anomalies
  • gold.ml_model_metrics: model KPIs, drift, lift, training time
Transformations between layers
  • Bronze to Silver: rename timestamp columns (tpep_, lpep_, pickup_datetime, dropOff_datetime) to pickup_ts and dropoff_ts; cast types; map trip_distance and trip_miles to distance_miles; map tip_amount and tips to a single tip column; add service_type; union all four trip sources; derive duration_sec; compute dq flags; deduplicate on source key and timestamps.
  • Silver to Gold: aggregate by date, hour, zone pair, and service type; filter by service_type where a KPI does not apply (for example, revenue excludes FHV because it has no fare fields).
  • Silver to Gold (batch history): roll daily results up to monthly grain, then add period-over-period change, rolling windows, and seasonality indexes. Each load writes one row to silver.batch_run_log, which feeds gold.batch_run_metrics.
  • Silver to ML to Gold: build silver.ml_features from silver.trips (lag, calendar, and zone features), train and score with Spark ML, and write predictions and model metrics to the gold.ml_* tables. Features exclude fields only known after the trip.

Scope note. FHV trips have no fare fields and no shared-ride match fields in the same form as HVFHV, so they appear only in volume, demand, zone, and efficiency marts. Silver keeps the full set of columns so the scope can be widened later without reprocessing Bronze. The monthly marts need the full history loaded, and the batch health KPIs need silver.batch_run_log to be written on every load, including the TLC publication date.
